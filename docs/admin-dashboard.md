# 관리자 대시보드

## 구현 계획과 상태

1. 역할 기반 진입: 완료. 로그인 직후 `/api/v1/auth/me`를 확인하여 관리자와 고객 작업공간을 분리한다.
2. 운영 개요: 완료. VM/CT 할당 현황, 활성·전체 사용자와 조직 수, 클러스터 연결, 활성 경보와 모든 등록 클러스터의 실시간 CPU·RAM·루트 디스크·load average·가동시간·VM/CT·스토리지 현황을 표시한다. 각 클러스터 카드에는 선택 노드의 CPU, server load, memory, network 미니 그래프와 CPU·IO·memory pressure stall을 포함한 7개 상세 그래프를 제공한다. 현재값은 10초, Proxmox RRD 시계열은 60초마다 갱신하며 브라우저 탭이 숨겨지면 요청과 타이머를 일시 중지한다. 한 클러스터 조회가 실패해도 나머지 클러스터 상태와 직전 정상 데이터는 유지한다. worker와 queue 세부값은 운영 API·Prometheus에서 제공한다.
3. 클러스터 운영: 완료. 등록, 연결 시험, 실시간 노드/VM/CT/스토리지 조회를 제공한다.
4. 접근 관리: 완료. 조직 상세에서 구성원과 할당 VM/CT를 함께 관리한다.
5. IPAM과 프로비저닝: 완료. IP 풀 생성/조회/수정/안전 삭제, 상품 생성, 템플릿과 요청 상태 조회를 제공한다.
6. 감사: 완료. `SUPER_ADMIN`에게 최근 append-only 감사 사건을 표시한다.
7. PBS 백업·복구: 완료. PVE의 PBS 스토리지 검색·대상 등록, 수동 백업, UPID 진행 상태, 내역 조회와 SUPER_ADMIN의 새 VMID 복구를 제공한다.
8. 품질 검증: 완료. 관리자와 고객 mock E2E, lint, TypeScript strict 검사, production build를 실행한다.

## 운영 사용

1. `docker compose exec backend alembic upgrade head`로 DB를 최신화한다.
2. `python -m app.cli.create_admin`으로 초기 관리자를 만든다.
3. `http://localhost:3000`에서 관리자 계정으로 로그인한다.
4. 운영 개요에서 worker와 queue 상태, 클러스터별 자원 사용률과 과부하 신호를 확인한다.
5. 클러스터 등록 시 `.env`의 `PVE_ALLOWED_HOSTS` 또는 `PVE_ALLOWED_NETWORKS` 정책을 먼저 설정한다.

클러스터 token secret은 입력 필드에만 존재하고 관리자 API 응답에는 포함되지 않는다. 브라우저 저장소에도 세션을 영속화하지 않는다.

## 현재 경계

- 클러스터 화면은 Proxmox API의 실시간 조회 결과다.
- 등록 해제된 클러스터의 VM/CT 투영은 이력 보존을 위해 물리 삭제하지 않지만, `is_present=false`로 전환하고 운영 목록에서는 제외한다.
- 운영 개요 그래프는 Proxmox 노드 RRD를 사용하며 1시간·6시간·24시간·7일 범위를 지원한다. PVE가 PSI RRD 필드를 제공하지 않으면 0으로 오인하지 않고 `지원 안 함`으로 표시한다.
- 관리자가 클러스터의 실시간 guest 목록을 명시적으로 가져와 `workloads` 로컬 투영을 생성한다.
- 가져오기는 `(cluster_id, vmid)` 기준으로 멱등 갱신하며 PVE 리소스를 생성하거나 삭제하지 않는다.
- 사용자와 조직 화면은 `조직`, `사용자`, `리소스 할당`의 전역 탭으로 나눈다. 조직 탭은 이름·ID 검색, 활성 상태 필터, 생성일·이름 정렬과 25개 단위 서버 페이지네이션을 제공하며 행을 선택하면 상세로 이동한다.
- 조직 상세는 구성원과 할당 VM/CT 탭, 목록 복귀, 검색형 빠른 조직 전환을 제공한다. 빠른 전환 선택기는 최근 10개 또는 검색 결과 10개만 렌더링하며 키보드 탐색을 지원한다.
- 조직 상세에서 현재 구성원, 할당된 VM/CT, 미할당 VM/CT를 함께 조회하고 할당·회수한다.
- 조직 구성원 화면에서 기존 고객을 연결하거나 새 `CUSTOMER` 계정을 생성해 선택한 조직에 즉시 추가한다. 계정 생성 후 구성원 연결만 실패하면 생성된 계정을 보존하고 기존 고객 선택에서 재시도하도록 안내한다.
- 구성원 제거는 고객 접근을 즉시 회수하고, 할당 회수는 진행 중 작업이 있으면 거부한다.
- 고객 포털은 VM마다 할당 조직 이름을 표시하고, 여러 활성 조직의 구성원인 고객에게 조직별 VM 개수와 가로 필터를 제공한다. 내부 조직 ID는 고객 응답에 노출하지 않는다.
- 템플릿 생성은 동기화된 source workload가 필요하므로 현재 화면에서는 기존 템플릿 조회만 제공한다.
- 백업 화면은 PVE에 이미 등록된 `pbs` 스토리지만 사용하며 PBS credential을 직접 받지 않는다. 자동 스케줄과 삭제/prune은 후속 범위다.
- 성공 백업의 상세 drawer에서 SUPER_ADMIN은 대상 node, 새 VMID와 이름을 지정해 복구한다. 기존 VMID 덮어쓰기는 지원하지 않는다.
- VM 목록에서 최근 백업 상태·시각·이번 전송량을 확인하고 해당 VM의 내역 관리 화면으로 이동할 수 있다.
- 논리 백업 크기와 PBS 중복제거 재사용분을 제외한 이번 실행 전송량을 구분해 표시한다.
- 관리자 MFA와 HttpOnly cookie 기반 세션은 운영 출시 전 후속 보안 작업이다.

후속 작업은 주기적 inventory sync, 누락 workload tombstone 처리, 프로비저닝 요청 작성 화면이다.
