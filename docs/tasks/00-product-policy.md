# 단계 0 — 제품 정책과 운영 기준 확정 (P0)

> 상태: 완료 (2026-07-24)
>
> 산출물: [제품 정책과 운영 기준](../deliverables/00-product-policy/product-policy.md)

## 목표

후속 기능 구현 중 권한, 데이터 보존, 고객 노출 범위가 반복해서 바뀌지 않도록 제품
정책을 먼저 고정한다.

## 결정할 항목

1. [x] 고객 workload는 초기 QEMU 전용으로 하고 LXC는 후속 검증 대상으로 둔다.
2. [x] 고객 backup은 초기 조회·실행·복구를 모두 금지한다.
3. [x] 조직 관리자는 플랫폼 역할이 아닌 organization membership 역할로 확장한다.
4. [x] 고객 사양 변경은 직접 실행이 아닌 승인 요청 방식으로 제공한다.
5. [x] 고객 성능 지표를 1분 24시간, 5분 30일, 1시간 365일 보존한다.
6. [x] 운영자 Slack·이메일과 고객 이메일을 1차 알림 채널로 사용한다.
7. [x] backup 보존과 prune의 기준 시스템은 PBS로 한다.
8. [x] 제품 경계를 과금 없는 멀티테넌트 인프라 운영 포털로 확정한다.
9. [x] RPO, RTO, stale, timeout과 SLO 초기 수치를 확정한다.
10. [x] 감사, 활동, metric과 session 데이터 보존 정책을 확정한다.

## 산출물

- 역할 × 기능 × 객체 소유권 권한 매트릭스
- QEMU/LXC 고객 제공 정책
- 알림 이벤트와 기본 수신자 목록
- 백업/복구와 보존 정책
- SLI/SLO 및 RPO/RTO 문서
- P1/P2/P3 범위 확정표

## 완료 조건

- [x] 모든 후속 API의 권한 주체와 객체 소유권 기준이 결정되어 있다.
- [x] 고객에게 보이는 정보와 숨길 PVE 내부 정보가 정리되어 있다.
- [x] 선택 기능과 필수 기능이 P1/P2/P3로 구분되어 있다.
- [x] 알림, backup, SLI/SLO, RPO/RTO와 데이터 보존 기준이 수치화되어 있다.
